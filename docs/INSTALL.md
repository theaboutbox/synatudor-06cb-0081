# Install on Arch Linux or Omarchy

This release supports the x86-64 Synaptics USB fingerprint reader
`06cb:0081`. The earlier bring-up was tested end to end on a Lenovo Yoga
C930-13IKB with Arch Linux and Omarchy. Package revision 12 has now passed
pairing, enrollment, and a fingerprint match on that system. Frequent retries
and pending persistence and recovery checks are recorded in
[Validation](VALIDATION.md). Other computers exposing
the same USB ID also need field testing.

Setup performs ordinary initialization, calibration, enrollment, and
verification. It never invokes the separate vendor-unpair maintenance
operation. That operation is available only through an explicit
`synatudor-reset-ownership` invocation, changes pairing and local enrollment
state, and may make existing Windows or Linux enrollments unusable. The pinned
vendor callback is not a proven secure erase of the sensor's template database.

## Quick start

Connect the reader, open a terminal as your regular desktop user, and run:

```bash
git clone https://github.com/theaboutbox/synatudor-06cb-0081.git
cd synatudor-06cb-0081
./scripts/install
```

The installer performs these steps:

1. Confirms that exactly one `06cb:0081` reader is present.
2. Installs the Arch build and runtime dependencies.
3. Builds the signed `libfprint-tod` tag `v1.95.2+tod1` when needed and lets
   pacman replace stock `libfprint` in a dependency-consistent transaction.
4. Downloads Lenovo's Windows driver from Lenovo, verifies its pinned SHA-256,
   extracts two DLLs without executing the installer, runs the test suite, and
   builds a local `synatudor-0081` package.
5. Installs the package, reloads udev and systemd, and starts guided setup.
6. With the sensor uncovered, makes up to three bounded ordinary initialization
   attempts. Between attempts it restarts the ordinary USB session so a vendor
   pairing transition can continue after re-enumeration in a new host process.
   It succeeds only after the exact pairing worker has finished, its capture
   strategy exists, and the complete biometric pipeline reports ready. If all
   attempts fail, setup stops without issuing a vendor-unpair request.
7. Lets the vendor driver generate calibration for that physical reader. It
   then enrolls and verifies the right index finger.
8. On Omarchy, adds fingerprint authentication for sudo, polkit, and the lock
   screen only after verification succeeds. Password fallback remains active.

The build takes place as your user. Only package installation, service control,
private device state, the enrollment client, and PAM configuration use `sudo`.

To install the driver now and enroll later:

```bash
./scripts/install --driver-only
synatudor-setup
```

Use another finger with, for example:

```bash
synatudor-setup --finger left-index-finger
```

Setup completes sudo authorization before showing scan instructions, then runs
only the enrollment client as root with the desktop username supplied explicitly:

```bash
sudo -v
sudo -n -- /usr/bin/fprintd-enroll -f right-index-finger "$USER"
```

This enrolls the desktop user's finger and avoids a separate polkit dialog during
enrollment. Keep the reader uncovered while authorizing, then follow the scan
prompts. Setup and verification run as the desktop user; no polkit policy is
changed. A manual `fprintd-enroll` invocation as a regular user can still print
`Enrolling` before showing its polkit password dialog; authorize with the
password before touching the reader.

On plain Arch, enrollment works but the helper leaves PAM unchanged. Configure
PAM according to your desktop or distribution after `fprintd-verify` succeeds.

## Pairing and first setup

The reader remembers its owner independently of files on Linux. A reader that
was paired by Windows, an older experimental build, or a Linux installation
whose private state was removed can reject the identity generated by this
installation. Copying an old identity file is not a reliable repair because
the vendor also persists pairing and cryptographic registry state.

The pinned DLL writes `SetOwnershipFailureCount` whenever `DoPairing` fails.
It is a generic attempt counter rather than an ownership verdict. Values one
through four can occur during a recoverable pairing transition that continues
after USB re-enumeration or in another host process. At its capped failure
state the vendor clears the relevant counter and returns an error. The saved
value is useful diagnostic context, but no nonzero value by itself authorizes
or triggers unpairing.

`OnPrepareHardware` starts the vendor's pairing work asynchronously. Normal
startup joins that exact worker after `OnD0Entry`, then requires the pinned
capture-strategy field to be nonnull. Only after that check does it expose the
WinBio adapters, open every pipeline stage, and require
`WINBIO_SENSOR_READY`. `OwnershipFailureDetected.bool` retains its historical
name, but it is now armed true before every fallible normal initialization so
a stale successful result cannot survive an early failure. A true value does
not prove an ownership mismatch. Only a complete safe pipeline open writes it
false. Capture rechecks the strategy before entering the vendor callback.

`synatudor-setup` performs up to three bounded normal starts with
`synatudor-reset` between failed attempts. It never invokes vendor unpairing.
After three failures it prints the vendor attempt count as a diagnostic and
asks you to inspect the service log before choosing the maintenance command
below.

You can request the same recovery directly while the driver is installed:

```bash
synatudor-reset-ownership
```

This is a destructive and risky maintenance operation: it changes pairing
state, removes local enrollment references, and can invalidate existing
enrollments. The host sends private WUDF control code `0x442040`, which the
pinned DLL dispatches through `OnResetOwnership` to `DoUnpairing`. This is a
vendor-specific callback, not the standard `IOCTL_BIOMETRIC_RESET`. Successful
completion proves that the callback returned success; static analysis does not
prove that it physically erased every sensor template. Do not use this command
as a secure-erase tool.

The standalone command names the physical reader and requires you to type its
full reset phrase. It stops and runtime-masks both fingerprint services, makes
a root-only backup below `/var/lib/tudor/migration-backups`, submits a
reader-scoped one-shot request, and waits for a durable result. The host
consumes the request before entering vendor code and suppresses only the exact
asynchronous pairing worker during this maintenance initialization, preventing
it from racing the unpair callback. An in-progress or successful result blocks
normal startup until protected cleanup reaches its durable boundary.

After the vendor callback reports success, the helper removes incompatible
local pairing state and this driver's fprintd metadata for every local user. It
also removes every legacy `.tpd` pairing record managed by this driver because
the old store does not map those files to physical readers; all removed records
are included in the private backup. The helper backs up unscoped calibration,
migrates it only when its embedded identity matches the attached reader, and
removes every value from the legacy location.

Before removing the one-shot transaction barrier, the helper durably sets
`OwnershipResetPendingValidation.bool`. It then performs up to three normal
initialization cycles, with an ordinary USB reset and a fresh host between
attempts. Only a complete safe pipeline open changes that marker from pending
to completed. If validation does not finish, the helper leaves both services
stopped behind its runtime masks. Rerun `synatudor-reset-ownership` to resume
only the normal validation step; the pending marker and absent transaction
prevent a second vendor-unpair request. The completed marker remains durable,
so a later invocation reports the prior result without issuing the callback.
Use `synatudor-reset-ownership --new` only to authorize a genuinely new
vendor-unpair operation. Run `synatudor-setup` to enroll again after validation
succeeds.

If the vendor callback times out or otherwise does not report success, its
physical outcome may be indeterminate. The one-shot request is never retried
automatically. A recovery invocation first makes any stale enabled request
harmless and stops. Only a later invocation with `--new` can authorize a
separate callback after the failed transaction is stable.

The `--yes` option bypasses the standalone phrase for deliberate automation.
The `--new` option explicitly authorizes another vendor-unpair operation when
a durable completed marker or a stable failed transaction already exists. It
does not override malformed state or combine repair of an enabled stale request
with a new callback in one invocation. `synatudor-setup` does not call this
command.

## Proprietary driver and private state

This repository and all source artifacts contain no Lenovo or Synaptics binary
and no fingerprint-reader state. GitHub's automatic archive for tag `v0.1.0`
is the complete repository snapshot. The separately attached
`synatudor-06cb-0081-0.1.0.tar.gz` is a smaller, deterministic build payload
consumed by `packaging/arch/PKGBUILD`; it deliberately omits packaging metadata
to avoid a circular archive checksum. During each local build, makepkg
downloads:

- `https://download.lenovo.com/consumer/mobiles/huy103af07m6.exe`
- SHA-256: `2713966a9ce5906fce12d33ead81f8c15a72d7b1cbe4e523613147181ce32343`

The two pinned DLLs are embedded only in the package built on your computer.
That package is stored with private permissions below
`~/.cache/synatudor-0081/packages/`; do not attach it to a public release.

Calibration is generated by the vendor driver on first initialization while
the sensor is uncovered. It is specific to the reader and is stored as root,
mode `0600`, below `/var/lib/tudor/devices/`. Reader-scoped pairing and
cryptographic state is stored there with the same protection. Pairing,
registry, calibration, on-sensor templates, and local fprintd references must
never be committed or shared.

## Updates and diagnostics

Rerun `./scripts/install` from an updated checkout. Existing device state and
enrollments are preserved. Reset a wedged USB transport without changing
enrollments with:

```bash
synatudor-reset
```

Build and test a package without installing or changing authentication with:

```bash
./scripts/install --build-only
```

This mode requires the exact tested `libfprint-tod` package
`1.95.2+tod1-1` and the build dependencies to be installed already. It does
not require a connected fingerprint reader or an interactive terminal.

## Manual makepkg path

The installer is a wrapper around the following Arch package build. This path
is useful for auditing each package transaction or adapting the process. Start
from a clean checkout of the release tag; `make-source-archive` reads the Git
commit itself, never modified or untracked worktree bytes.

Install the build dependencies and import the full fingerprint of the key that
signed the pinned `libfprint-tod` tag:

```bash
sudo pacman -S --needed \
  base-devel dbus fprintd git glib2 glib2-devel gnutls innoextract \
  json-glib libcap libgudev libgusb libseccomp libusb meson ninja \
  openssl pixman pkgconf python-cairo python-gobject sudo systemd \
  usbutils util-linux
gpg --keyserver hkps://keyserver.ubuntu.com --recv-keys \
  D4C501DA48EB797A081750939449C2F50996635F
```

Build and install the exact TOD-enabled libfprint package:

```bash
repo_root=$PWD
package_dir=$repo_root/dist
source_dir=$package_dir/sources
mkdir -p "$package_dir" "$source_dir"
(
  cd packaging/libfprint-tod
  PKGDEST="$package_dir" SRCDEST="$source_dir" \
    makepkg --cleanbuild --clean --noconfirm
)
sudo systemctl stop fprintd.service 2>/dev/null || true
sudo pacman --noconfirm --ask=4 -U \
  "$package_dir/libfprint-tod-1.95.2+tod1-1-x86_64.pkg.tar.zst"
```

Then create the source payload from the checked-out commit, pass its checksum
to the driver PKGBUILD, and install the resulting local-only package:

```bash
payload=$package_dir/synatudor-06cb-0081-0.1.0.tar.gz
./scripts/make-source-archive "$payload" HEAD
payload_sha256=$(sha256sum "$payload" | awk '{print $1}')
(
  cd packaging/arch
  SYNA_TUDOR_SOURCE_URL="file://$payload" \
  SYNA_TUDOR_SOURCE_SHA256="$payload_sha256" \
  PKGDEST="$package_dir" SRCDEST="$source_dir" \
    makepkg --cleanbuild --clean --noconfirm
)
sudo systemctl stop fprintd.service tudor-host-launcher.service \
  2>/dev/null || true
sudo pacman --noconfirm -U \
  "$package_dir/synatudor-0081-0.1.0-11-x86_64.pkg.tar.zst"
sudo systemctl daemon-reload
sudo udevadm control --reload
sudo systemctl start tudor-host-launcher.service
sudo systemctl reset-failed fprintd.service
sudo systemctl start --no-block fprintd.service
synatudor-setup
```

The release PKGBUILD already contains the published payload checksum, so the
two `SYNA_TUDOR_SOURCE_*` overrides are needed only when building a payload
from a local commit.

Useful read-only checks are:

```bash
pacman -Q synatudor-0081 libfprint-tod fprintd
systemctl status tudor-host-launcher.service fprintd.service
fprintd-list "$USER"
```

## Uninstall and rollback

Use the supplied command instead of Omarchy's stock fingerprint removal command
so the saved PAM transaction and the replaced libfprint provider are handled:

```bash
synatudor-uninstall
```

This disables the managed PAM entries first, removes `synatudor-0081`, restores
stock `libfprint` when the installer replaced it, and preserves device state in
`/var/lib/tudor` for a later reinstall.

To also delete the current user's enrolled fingerprints and Tudor device state:

```bash
synatudor-uninstall --purge
```

Purging removes local Tudor state and fprintd metadata. It does not invoke the
vendor's reader-side unpair callback. If you deliberately need that callback,
run `synatudor-reset-ownership` before uninstalling while the vendor driver is
still available. Treat it as pairing maintenance, not as a proven sensor
template erase.

PAM rollback is checksummed and transactional. If an Omarchy update or manual
edit changed a managed block, rollback stops before altering it and leaves the
driver installed so the conflict can be reviewed safely.
